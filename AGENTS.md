# hireloop-client

Turborepo + npm-workspaces starter for the HireLoop web client. The only deployable app is `apps/web` (Next.js App Router); `packages/ui` is the shared shadcn/Base UI library, consumed as source with no build step.

## Commands (run from repo root)

- `npm install` — npm 11 and Node >=20.9. `package-lock.json` is the only lockfile; the README's `pnpm` command is stale.
- `npm run dev` / `build` / `lint` / `format` / `typecheck` — run the task across packages via Turbo.
- Single app: `npx turbo dev --filter=web` or `npm run dev -w web`. For `lint`/`typecheck`, Turbo still runs dependency tasks because `turbo.json` uses `dependsOn: ["^task"]`.
- Verify changes with `npm run lint && npm run typecheck && npm run build`. There is no test runner, CI, or env file yet; don't invent test commands.

## Structure and conventions

- `apps/web/app` holds routes and layouts. Aliases: `@/*` → `apps/web/*`; `@workspace/ui/*` → `packages/ui/src/*`.
- Put shared components in `packages/ui/src/components` and import them as `@workspace/ui/components/<name>`. `apps/web/components` is app-only (currently just the theme provider).
- `packages/ui` is transpiled from source (`transpilePackages`); don't add a build step. Its `exports` cover only `globals.css`, `postcss.config`, `lib/*`, `components/*`, and `hooks/*`; add an export when introducing another top-level directory.
- `cn` is re-exported from the `cn` package by `@workspace/ui/lib/utils`. Don't add `clsx` or `tailwind-merge`.
- Tailwind v4 is CSS-first: there is no `tailwind.config.*`. Theme tokens and `@source` globs live in `packages/ui/src/styles/globals.css`, imported once by `apps/web/app/layout.tsx`; the PostCSS config is shared.
- shadcn uses the `base-nova` style with Base UI (`@base-ui/react`), not Radix. Add components from the root with `npx shadcn@latest add <name> -c apps/web`; this writes to `packages/ui/src/components`.
- Prettier: no semicolons, double quotes, LF, 80 columns, Tailwind class sorting for `cn`/`cva`. Apply with `npm run format`.
- ESLint 10 flat config lives in each workspace (`apps/web/eslint.config.js`, `packages/ui/eslint.config.js`); the root `.eslintrc.js` is legacy and not loaded, and `next lint` was removed in Next 16. `eslint-plugin-only-warn` downgrades every rule to a warning, so a clean exit does not mean clean lint.
- TypeScript is strict with `noUncheckedIndexedAccess`; the app uses Bundler resolution while `packages/ui` uses the NodeNext base config.
